# پیشنهاد همکاری به استادتمام — CLCRec Lab Kit

مخاطب این سند: استادتمام دانشگاه صنعتی که در سامانه‌های توصیه‌گر، یادگیری بازنمایی، یا بازیابی اطلاعات کار می‌کند.

هدف فروش: **خرید لایسنس آزمایشگاه، قرارداد همکاری پژوهشی، یا تعریف طرح ارتباط با صنعت** — نه فروش فایل پایتون MovieLens.

---

## ۱. نامهٔ معرفی (قابل کپی در ایمیل)

```
استاد گرامی،

یک بستهٔ آزمایشگاهی برای مسئلهٔ item cold-start آماده کرده‌ام که
مستقیماً روی مقالهٔ CLCRec (Wei et al., ACM MM 2021) بنا شده و
برای سه کار طراحی شده است:

  ۱) تدریس تحصیلات تکمیلی — پیاده‌سازی شفاف InfoNCE / SVD / encoder
     بدون جعبهٔ سیاه، با پروتکل ارزیابی قابل دفاع در جلسهٔ دفاع
  ۲) زیرساخت پایان‌نامه و مقاله — مقایسه با baseline خطی (خانوادهٔ CB2CF)،
     فاصلهٔ اطمینان بوت‌استرپ، و API برای آزمایش‌های دانشجو
  ۳) هستهٔ طرح ارتباط با صنعت — سرویس HTTP برای کالای تازه‌وارد،
     آمادهٔ اتصال به کاتالوگ واقعی کارفرما

تمایز نسبت به ریپوی رسمی مقاله و دموهای آموزشی رایج:
  • نشت تعامل آیتم سرد به SVD بسته شده است
  • بازنمایی کاربر فقط از آیتم‌های گرم ساخته می‌شود
  • Recall@K و NDCG@K با فاصلهٔ اطمینان گزارش می‌شود
  • آیتم جدید (عنوان + ژانر + سال) بدون بازآموزش embed می‌شود

سه بستهٔ همکاری در انتهای همین نامه آمده است.
اگر موافق باشید، یک جلسهٔ ۲۰ دقیقه‌ای دموی زنده می‌گذارم:
جدول ارزیابی + یک آیتم ساختگی که همین لحظه وارد کاتالوگ می‌شود.

با احترام
```

## ۲. چیزی که استاد می‌خرد (و چیزی که نمی‌خرد)

استادتمام **وزن MovieLens** یا ادعای «بهتر از نتفلکیس» نمی‌خرد.

می‌خرد:

| دارایی | چرا برای آزمایشگاه ارزش دارد |
|---|---|
| پروتکل ارزیابی قابل دفاع | در داوری مقاله و جلسهٔ دفاع گیر نمی‌کند |
| کد شفاف NumPy | دانشجوی درس، گرادیان InfoNCE را خط‌به‌خط می‌بیند |
| API و سرویس | برای کارفرما و درس «پیاده‌سازی صنعتی» قابل نمایش است |
| سه بستهٔ حقوقی مشخص | گرنت، پایان‌نامه، طرح صنعت هر کدام مسیر جدا دارند |
| شما به‌عنوان مجری فنی | استاد زمان پیاده‌سازی ندارد؛ بودجه دارد |

کدِ عمومی روی گیت‌هاب نقش **نمونهٔ فنی** را بازی می‌کند. پولی که رد و بدل می‌شود بابت **لایسنس نهادی + انتقال دانش + پشتیبانی + توسعهٔ سفارشی + طرح صنعت** است.

## ۳. وضعیت فنی بسته (آنچه در جلسه نشان می‌دهید)

دستورهای دمو:

```bash
python main.py --protocol academic
python main.py --demo-new-item --title "Dune (2021)" --genres "Action|Adventure|Sci-Fi"
python main.py --serve
```

خروجی قابل ارائه به استاد:

- جدول COLD و ALL-item برای CLCRec در برابر `Ridge-Map` و `Raw-Content`
- `artifacts/metrics.json` برای گذاشتن در پیوست پروپوزال گرنت
- `POST /v1/new_item` : آیتمی که هیچ تعاملی ندارد، همسایه می‌گیرد

ادعاهایی که **نباید** بکنید:

- این پیاده‌سازی عین مدل multimodal رسمی (ResNet / VGGish / Sentence2Vec) نیست
- TikTok / Kwai / Amazon کاغذ در این بسته نیستند
- عدد HR@10 دموی قدیمی روی پروتکل legacy است؛ پروتکل academic سخت‌تر و درست‌تر است

صداقت اینجا اعتبار می‌خرد. استاد این حوزه پروتکل غلط را در پنج دقیقه می‌بیند.

## ۴. سه بستهٔ قابل فروش

رقم‌ها نقطهٔ شروع مذاکره است؛ با عرف گرنت و طرح ارتباط با صنعت دانشگاه تنظیم کنید.

### بستهٔ الف — لایسنس آزمایشگاه (خرید یک‌جا)

**برای چه کسی:** استاد می‌خواهد درس یا آزمایشگاه RecSys داشته باشد.

| مورد | شرح |
|---|---|
| محتوا | کد کامل، جلسهٔ انتقال ۳ ساعته، دفترچهٔ تمرین دانشجو، ۳ ماه رفع‌اشکال |
| حق استفاده | تدریس و پژوهش داخل همان آزمایشگاه / گروه |
| حق انتشار کد | ندارد، مگر با ذکر لایسنس و بدون واگذاری مالکیت |
| مبلغ پیشنهادی | ۴۸ میلیون تومان |
| زمان تحویل | یک هفته پس از پیش‌پرداخت |

اگر استاد بگوید «کد که روی گیت‌هاب است»، جواب این است: گیت‌هاب ارزیابی شخصی است؛ تدریس کلاسی، تکثیر بین دانشجویان به‌عنوان تکلیف رسمی، و گذاشتن در پروپوزال گرنت، استفادهٔ نهادی است و لایسنس می‌خواهد. جایگزین نرم‌تر: بستهٔ الف را به‌صورت **کارگاه + پشتیبانی** بفروشید تا مقاومت حقوقی کم شود.

### بستهٔ ب — همکاری پژوهشی ۱۲ هفته (مقاله / پایان‌نامه)

**برای چه کسی:** استاد دانشجو دارد و می‌خواهد خروجی ISI / کنفرانس یا فصل پایان‌نامه بگیرد.

| مورد | شرح |
|---|---|
| محتوا | شما مجری فنی هستید؛ استاد ناظر علمی |
| خروجی | یک امتداد قابل‌مقاله (مثلاً multimodal، دیتاست دوم، یا مقایسه با DropoutNet/Heater) + کد آزمایش‌ها + جداول |
| نویسندگی | قابل مذاکره؛ پیش‌فرض: شما نویسندهٔ اول فنی، استاد corresponding |
| مبلغ پیشنهادی | ۸۵ میلیون تومان (یا ۳ قسط) |
| مالکیت کد آزمایش‌های مشترک | مشترک؛ انتشار مقاله منوط به توافق کتبی |

این معمولاً **راحت‌ترین بله** از استادتمام است، چون شبیه گرفتن پژوهشگر طرح است نه «خرید نرم‌افزار».

### بستهٔ ج — طرح ارتباط با صنعت (بزرگ‌ترین رقم)

**برای چه کسی:** استاد می‌تواند کارفرما بیاورد (فروشگاه، رسانه، مارکت‌پلیس، اپراتور) یا از دفتر ارتباط با صنعت دانشگاه طرح تعریف کند.

| مورد | شرح |
|---|---|
| نقش استاد | مجری دانشگاه، اعتبار علمی، امضای قرارداد |
| نقش شما | مجری فنی، تحویل API و گزارش uplift |
| خروجی | موتور cold-start روی کاتالوگ کارفرما، ویجت/API، گزارش A/B |
| رقم طرح (به کارفرما) | از ۲۸۰ میلیون تومان (پایلوت ۸–۱۲ هفته) تا بالاتر |
| سهم‌بندی پیشنهادی | بالاسری دانشگاه طبق آیین‌نامه + ۳۰–۴۰٪ استاد مجری + ۴۰–۵۰٪ مجری فنی |
| شرط شروع | دادهٔ واقعی کارفرما یا نمونهٔ ناشناس‌شده |

این بسته را به استاد به‌عنوان **طرح آمادهٔ ارسال به دفتر ارتباط با صنعت** بدهید، نه به‌عنوان فروش کد.

## ۵. مسیر جلسه تا امضا

1. ایمیل نامهٔ بالا + همین فایل به‌صورت PDF.
2. جلسهٔ ۲۰ دقیقه‌ای: یک جدول + یک آیتم جدید + «سه بسته».
3. اگر استاد علمی است → بستهٔ ب. اگر درس می‌خواهد → الف. اگر کارفرما دارد → ج.
4. پیش‌فاکتور یک صفحه‌ای + ۲ هفته فرصت ارزیابی فنی رایگان روی همین ریپو.
5. قرارداد کوتاه: موضوع، مبلغ، خروجی، مالکیت فکری، محرمانگی دادهٔ کارفرما.

سر جلسه مدل را با پروتکل legacy «قهرمان» نکنید. پروتکل academic را نشان بدهید و بگویید دموی قدیمی را عمداً کنار گذاشتید چون نشت داشت. این جمله برای استادتمام از هر عدد HR مهم‌تر است.

## ۶. امتدادهایی که دانشجو می‌تواند مقاله کند

این فهرست را به‌عنوان «نقشهٔ پایان‌نامه» روی میز بگذارید:

1. افزودن شاخهٔ U-I مقاله (الان هستهٔ R-E / InfoNCE محتوا–مشارکتی پیاده شده)
2. مقایسه با DropoutNet / Heater / CB2CF روی همان پروتکل
3. ویژگی تصویر (CLIP) به‌جای TF-IDF عنوان
4. دیتاست دوم: Amazon Reviews یا CiteULike
5. سردی کاربر و نشست، نه فقط آیتم
6. آزمایش صنعتی: کاتالوگ فروشگاهی + متریک CTR به‌جای Recall

هر کدام از این‌ها یک فصل یا یک submission است. ارزش بستهٔ ب همین است.

## ۷. مالکیت فکری (جملهٔ آماده برای قرارداد)

- حق‌نشر کد فعلی متعلق به ارائه‌دهنده است.
- لایسنس آزمایشگاه حق استفاده می‌دهد، حق واگذاری نمی‌دهد.
- در طرح صنعت، داده و مدل fine-tune شده روی دادهٔ کارفرما متعلق به کارفرما است؛ هستهٔ الگوریتم طبق قرارداد لیسانس می‌شود.
- مقالهٔ مشترک بدون رضایت کتبی طرفین submit نمی‌شود.
